## Cross-cutting decisions (binding on every fixer)

1. master_extraction.csv gains two columns, already added to the header in this copy, after `n_tested`: `pre_post_r` (correlation between pre and post measurements for within-person designs, as printed or derivable; blank if not reported) and `is_primary_outcome` (`yes`/`no`; exactly one `yes` per study × ability; set by the head agent at reconciliation, not by extractors). SCHEMA.md documents both (fixer C).
2. Effect sizes are computed by analysis code from the master file (SCHEMA convention), never hand-built. New script analysis/01_effect_sizes.R writes analysis/outputs/effect_sizes.csv with exactly these columns:
   `es_id, study_id, ability_id, outcome_measure, timepoint, design, lever_type, measure, yi, vi, n_i, n_c, is_primary_outcome, synthetic, derivation`
   `measure` ∈ {SMD (independent groups: rct, nonrandomised_comparison), SMCR (within-person: pre_post, crossover; uses pre_post_r or the placeholder), PLO (prevalence: logit proportion from n_responders/n_tested), OR (log odds ratio from two binary rows), Z (Δ/σ_pop with delta-method variance, only where a `verified` population_sd row exists)}. `synthetic` is `yes` when study_id starts with `synth_`.
   SE→SD: sd = se·√n. CI95→SD: sd = (hi−lo)/(2·1.96)·√n. Recorded in `derivation`.
3. Placeholder pre/post correlation: when `pre_post_r` is blank for an SMCR row, r = 0.5 is used, with sensitivity runs at 0.3 and 0.7. Declared once in analysis/constants.R as `R_PREPOST_DEFAULT`, labelled "placeholder pending the statistician co-author's decision at Gate 5" everywhere it is mentioned.
4. Pooling unit: ability_id × measure, using rows with `is_primary_outcome = yes` only; non-primary rows are reported individually. (Dependent effect sizes: multilevel alternative is a Gate 5 decision; say so in a comment.)
5. freq_pooled.csv always has the columns `ability_id, measure, outcome_measure, k, est, ci_lb, ci_ub, pi_lb, pi_ub, tau2, I2, p, note` (NA where not pooled). freq_individual.csv has `es_id, study_id, ability_id, measure, outcome_measure, yi, ci_lb, ci_ub, k_ability` for every row (ci = yi ± 1.96·√vi; back-transformed for PLO in extra columns `est_natural, ci_lb_natural, ci_ub_natural`). bayes_pooled.csv has `ability_id, measure, k, mu_mean, mu_lb, mu_ub, tau_median, p_mu_gt_0.2, p_mu_gt_0.5, pred_lb, pred_ub, bf_10, mu_mean_wider, mu_mean_tighter, note`; only SMD/SMCR/Z measures run through the declared SMD-scale priors; PLO/OR rows get a note row ("Beta-binomial / logit model: Gate 5"). Every bayesmeta call is wrapped in tryCatch and the error goes to `note`; the script must not halt when bayesmeta is absent — it writes note rows and a warning.
6. grade_draft.csv header: `ability_id, outcome, n_studies, n_participants, design_mix, starting_level, rob_downgrade, inconsistency_downgrade, indirectness_downgrade, imprecision_downgrade, publication_bias_downgrade, large_effect_upgrade, dose_response_upgrade, opposing_confounding_upgrade, draft_certainty, reasons, plain_language_statement, rater_id, date, skill_version, model`. grade_final.csv = the same columns plus `final_certainty, final_rater_id, final_date, change_reason, signed`. `outcome` equals the primary row's `outcome_measure` string, so 03_sof.R joins on `ability_id` + `outcome`.
7. Screening: a review, meta-analysis or overview is `decision = exclude`, `exclusion_code = E7`; the word `harvest` is no longer a code value (SCHEMA and skill agree). E7 is tested first, then E1…E5, E8. E6 (duplicate) is applied by the head agent during deduplication, never by a screener.
